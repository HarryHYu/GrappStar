  renders and section cuts yourself.

- Anything that runs on the Jetson: Python 3.10 (JetPack 6.2, Ubuntu 22.04), few dependencies (numpy, opencv, pyserial;
  anything else must be justified and listed in jetson/requirements.txt).

## Hardware facts every worker needs

- Base MCU: ESP32-S3 DevKitC-1-N8, USB to the Jetson (also powers the board).
- Wiper motor: BTS7960 module on the 3S LiPo (12.6 V full) behind a 20 A fuse. Dimensions unknown until Harry measures:
  keep the interface parametric.
- Selector drum N20 on DRV8833 #3. DRV8833 VM max is 10.8 V, so the 3S cannot feed it directly: plan a buck (MP1584)
  set to about 9 V, and flag it if Harry has no spare.
- Sensors: Adafruit AS5600 (STEMMA QT) on the wiper output shaft. Printed contact switches (M3 screw head touching an M3
  nut, ESP32 internal pull-up, firmware debounce). No microswitches. Optional 100 kg load cell + HX711 (to confirm).
- Dart: XIAO ESP32S3 AP at 192.168.4.1, HTTP API (`kedge/fw/kedge_dart`, `kedge/fw/jetson/kedge_client.py`).
- Video: Caddx Ant on the dart, 5.8 GHz VTX, RC832 receiver on the rover, DIGITNOW USB capture (UVC) into the Jetson.
  Rover camera: Razer Kiyo X (UVC). YOLOv8n already ran on the Jetson in August.
- Rover: Jetson Orin Nano Super, 3S 5200 mAh LiPo. Drive train details unknown (to confirm with Harry).

## Contracts between workers (v1; propose changes in REPORT.md, never break them silently)

### C1. Base <-> Jetson: USB serial, JSON lines

- Port: the DevKitC native USB port (USB CDC). Newline-terminated JSON objects, UTF-8, at most 256 bytes per line.
- Jetson to base: `{"id": 17, "cmd": "aim", "deg": 32.5}`. Every command gets exactly one reply:
  `{"id": 17, "ok": true}` or `{"id": 17, "ok": false, "err": "NOT_IN_LAUNCH"}`. Extra fields allowed.
- Base to Jetson, unsolicited: telemetry `{"tel": {...}}` at 10 Hz (20 Hz while anything moves) and events
  `{"evt": "FIRED", ...}`.
- Commands: `ping`, `status`, `stop` (wiper off now, drum holds), `estop` (wiper off, drum to NEUTRAL),
  `clear` (clear a fault), `mode` {to: LAUNCH|NEUTRAL|REEL}, `aim` {deg}, `arm` (returns {token}, valid 3 s),
  `fire` {token}, `wrap`, `unwrap`, `reel` {duty 0..1, max_n, until: seated|tension|stop}, `jog` {motor: wiper|drum,
  dir: 1|-1, ms}, `cal` {what}, `set` {key, val}, `get` {key}.
- Telemetry fields: `state`, `mode`, `drum_deg`, `drum_pos` (LAUNCH|NEUTRAL|REEL|WRAPPED|BETWEEN|UNKNOWN),
  `wiper_deg` (multi-turn), `rpm`, `amps`, `pitch_deg`, `cock` (0..1), `wraps`, `line_m`, `tension_n` (null without a
  load cell), `sw` (object of named contacts), `fault` (code or null), `vbat`.
- Events: MODE, AIMED, COCKED, FIRED, WRAPPED, UNWRAPPED, SEATED, STALL, LIMIT, FAULT.
- Fault codes: STALL, OVERCURRENT, DRUM_TIMEOUT, DRUM_SENSOR, ANGLE_SENSOR, SWITCH_DISAGREE, BROWNOUT, BAD_STATE.
- `fw-base` owns the final `firmware/base/PROTOCOL.md`; `jetson` implements against it and ships a mock base for tests.

### C2. Dart <-> Jetson: HTTP on the dart AP

- Keep the existing `/status`, `/key?c=&ms=`, `/stop`, `/auto`.
- Add `GET /release`: the release sequence (drills out, foot out, kick back, deploy up), mirroring `/auto`.
- Add `phase` to `/status`: IDLE|ARMED|FLIGHT|LANDED|ANCHORING|ANCHORED|RELEASING|FAULT.
- Add `GET /flightlog`: `{"hz": 50, "t_launch_ms": ..., "t_land_ms": ..., "samples": [[t_ms, qw, qx, qy, qz, ax, ay,
  az], ...]}` from a 12 s ring buffer, frozen from 2 s before launch detection (|a| over 4 g for 20 ms) until 3 s after
  landing (impact over 3.5 g, then still for 1 s; D28: the BNO085 clips at 8 g and filters).
- `fw-dart` owns the final API doc in `firmware/dart/API.md`.

### C3. Ballistics table

- `base/out/ballistics.json`: `{"version": 1, "pitch_min": ..., "pitch_max": ..., "drag_n": [0.5, 0.75, 1.0],
  "table": [{"pitch_deg": ..., "v_muzzle": ..., "range_m": [r05, r075, r10], "t_flight_s": [...], "apex_m": [...]}]}`.
- Written by the base physics model. The Jetson solver interpolates it and ships a placeholder until it exists.

### C4. Video devices

- Dart video: DIGITNOW capture, V4L2 `/dev/video*`, UVC, typically 720x480 (NTSC) or 720x576 (PAL), YUYV or MJPEG.
- Rover camera: Kiyo X, V4L2, up to 1920x1080 MJPEG. Force YUYV or MJPEG explicitly (JetPack JPEG library mismatch).
